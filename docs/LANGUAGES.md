# Interface languages

Quiznet bundles English, Arabic and Spanish. Select a language in **Settings → Language**. The choice is a device preference in `display.json`, separate from the library. Switching applies immediately and survives restart. Every language works offline.

The registry and message catalogs support additional languages without a fixed maximum. Adding twenty languages does not require twenty UI branches. Native language names remain visible so a user can find their way back after changing languages.

## Add or update a language

1. Add an entry to `src/ui/languages.js`: a safe language ID, native name, English name, valid `Intl` locale and `ltr` or `rtl` direction. Add the English name to every message catalog if it is new.
2. Copy `src/ui/locales/en.json` to `<id>.json`. Translate values, keeping message keys and named placeholders unchanged. English source phrases serve as readable keys; use semantic keys for messages such as plural counts. Do not translate storage IDs, action names, CSS values, file extensions or import schema fields.
3. Translate complete plural messages using the categories reported by `new Intl.PluralRules(locale).resolvedOptions().pluralCategories`. Arabic needs zero, one, two, few, many and other. English needs one and other; Spanish also has many. Counts receive numeric `count` and formatted `n`; a form can omit a number when the language expresses it naturally.
4. Run `npm run locales:sync` to validate catalogs and regenerate their browser `.js` files. Commit both JSON and generated JS. `npm run check` verifies matching keys, placeholders, plural forms, language metadata, plain text and generated bytes. It also checks literal UI message references and shared display metadata.
5. Check the affected workflows with synthetic study material: live switching and restart, Settings search, a narrow enlarged window, keyboard controls, dialogs, quiz/review/editor screens, and unchanged questions, answers, drafts and library files. Follow the normal full Windows release checks before packaging.

## Use messages safely

Use `tr(key, params)` for text and existing escaping when inserting that result in HTML. `trHtml(key, params)` escapes catalog text and accepts **already-rendered, trusted UI fragments** as placeholders. Keep each user value escaped by `esc` or processed through the existing safe rich-content renderer before passing it into a fragment. Never pass raw user input as a rendered fragment. Catalog values cannot contain HTML or angle brackets. Prefer full sentences with placeholders to translated word fragments or English plural suffixes.

Register fixed catalogs only. Language loading uses a registry-validated local script path; there is no remote service, arbitrary language-file import or renderer networking. English is the fallback for missing messages. An unavailable language pack falls back to English without rewriting the saved preference or library. Older preferences acquire English on read without being rewritten. Translation files are checked at build time; the runtime fallback also protects incomplete developer builds.

Shared question types, practice presets and instruction fields retain their stable IDs and original data contracts. Translate their labels when rendering controls. Custom course names, custom preset names, question text, answer choices, notes, code, filenames, imports, copied study material, exported reports and generated AI instructions retain their original content. Selecting an interface language does not select the language of an AI-generated quiz; that has a separate Quiz language field. The exact MIT notice and technical names remain original. System error details and advanced import diagnostics can retain their source wording.

## Layout, dates and input

Set `lang` and `dir` on the root document. Use CSS logical properties for spacing and alignment. Mirror directional navigation icons and horizontal quiz keys, while keeping native window controls in their Windows order. Mixed study text uses its own direction; code, math, paths, timers and answer letters remain isolated. A language change does not reorder stored choices or change an active attempt.

Use the shared `i18n.number`, `i18n.count` and `i18n.date` helpers for formatted UI values. Stored timestamps and review day keys stay unchanged; UI dates use the Gregorian calendar. The scheduler still follows local midnight. Keyboard answer selection accepts Latin, Arabic-Indic and Persian digits. Settings search can find localized controls through their English source terms, and language search ignores accents.

Useful references: [plural categories in Intl.PluralRules](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules), [HTML direction guidance](https://www.w3.org/International/questions/qa-html-dir) and [the dir attribute](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/dir).
